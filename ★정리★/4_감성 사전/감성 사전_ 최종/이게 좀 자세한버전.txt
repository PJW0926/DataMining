[코덱스실험16.py 발표용 특징 정리]

1. 프로젝트 한 줄 소개

단어의 긍정·부정 점수를 단순 합산하지 않고, 문맥과 평가 대상을 검증한 감성 근거를 영역별로 반영하여 맛집 리뷰의 별점을 산출하는 설명 가능한 규칙 기반 감성분석 시스템이다.


2. 기존 감성사전 방식의 문제

기존 방식은 리뷰에서 발견한 감성 단어의 점수를 단순 합산하기 때문에 문장 전체 의미를 놓칠 수 있다.

예시:
"가격은 비싸지만 음식은 맛있고 다시 방문할 의사가 있다."

단순 감성사전 방식:
- 비싸다: -1
- 맛있다: +1
- 총점: 0

이 방식은 리뷰 전체가 긍정적이라는 점과 "재방문 의사"라는 중요한 신호를 충분히 반영하지 못한다.


3. 전체 분석 과정

리뷰 원문 및 토큰
→ 토큰화 오류 보정
→ 감성사전 기반 n-gram 매칭
→ 명확한 문장형 phrase/pattern 탐지
→ 문맥과 평가 대상 검증
→ 감성 근거(evidence_items) 생성 및 중복 제거
→ 음식·서비스 등 영역별 점수 계산
→ 과소평가·과대평가 보정
→ 최종 감성 별점(sentiment_star) 생성


4. 핵심 기능과 장점

[1] Token n-gram 기반 감성사전 매칭

- 하나의 단어뿐 아니라 여러 토큰으로 구성된 감성 표현도 탐지한다.
- 긴 표현부터 먼저 매칭한다.
- 긴 표현에 포함된 짧은 표현을 다시 계산하지 않아 중복 감점을 방지한다.

예시:
"너무 맵다"가 탐지되면 내부의 "맵다"를 다시 감점하지 않는다.


[2] 토큰화 오류 보정

- 형태소 분석 과정에서 깨진 표현을 분석 전에 보정한다.
- 기존 tokens는 보존하고 감성분석에는 tokens_fixed를 사용한다.
- 원문에 없는 위험한 감성 토큰이 생성된 경우 잘못된 감점을 차단한다.

장점:
감성사전에 표현이 있어도 토큰화 오류 때문에 탐지되지 않거나, 원문에 없는 단어가 감점되는 문제를 줄일 수 있다.


[3] Token 매칭과 문장형 Phrase Rule 결합

단어 사전만으로 잡기 어려운 명확한 표현은 리뷰 원문에서 직접 탐지한다.

예시:
- 재방문 의사 있음
- 줄 설만하다
- 후회 없는 선택
- 서울 최고
- 백점 만점에 95점
- 게눈 감추듯 사라짐

장점:
긴 긍정 리뷰가 사전 단어 부족 때문에 낮게 평가되는 문제를 보완한다.


[4] Evidence 기반 점수 계산

탐지된 표현을 바로 최종 점수에 더하지 않고 evidence_items라는 감성 근거로 관리한다.

각 evidence에는 다음 정보가 포함된다.
- 탐지된 감성 표현
- 조정 전 점수와 실제 반영 점수
- 평가 영역
- 사전, phrase rule 등 탐지 출처
- 문맥에 따라 점수가 조정된 이유
- 최종 점수 반영 여부

예시:
- 맛있다:+1[token]
- 빠르게:1→0[speed_not_service_context]
- 비싸다:-0.5[token]

장점:
- 어떤 근거 때문에 별점이 올라가거나 내려갔는지 확인할 수 있다.
- 잘못 탐지된 표현도 삭제하지 않고 비활성 근거로 남겨 오류 원인을 추적할 수 있다.
- matched_words에만 표시되고 실제 점수에는 반영되지 않는 문제를 방지한다.


[5] 문맥에 따른 감성 점수 조정

같은 단어라도 실제 사용 문맥에 따라 유지, 중립화 또는 조정한다.

예시:
"웨이팅은 힘들지만 기다릴 가치가 있다."

- "힘들다"만 보고 무조건 부정으로 결론 내리지 않는다.
- "기다릴 가치가 있다"라는 긍정 근거를 함께 반영한다.

예시:
"조금 매콤하지만 맛있다."

- "맵다"를 무조건 부정으로 감점하지 않는다.
- 맛의 균형과 긍정 문맥을 확인한다.

예시:
"반반보쌈 소짜"

- 메뉴 크기를 의미하는 "소짜"를 짠맛의 "짜다"로 오인하지 않는다.

장점:
단어 자체보다 리뷰에서 실제로 사용된 의미를 우선하며, 애매하면 무리하게 반전하지 않고 0점 처리한다.


[6] 평가 대상과 시점 구분

리뷰 속 감성 표현이 현재 식당에 대한 실제 평가인지 검증한다.

구분하려는 문맥:
- 다른 식당에 대한 평가
- 다른 사람의 후기를 인용한 표현
- 과거 평가와 현재 평가
- 기대·명성과 실제 경험
- 반어적 표현

예시:
"본점은 맛있는데 여기는 아쉽다."

- "맛있다"를 현재 식당의 긍정 근거로 잘못 반영하지 않도록 한다.

예시:
"예전에는 맛있었지만 지금은 별로다."

- 과거 긍정보다 현재 부정 평가를 중요하게 반영한다.

장점:
감성 단어의 존재만 보는 것이 아니라, 무엇을 언제 평가했는지를 일부 구분할 수 있다.


[7] Aspect별 감성분석

리뷰 감성을 하나의 총점으로 바로 합산하지 않고 다음 영역으로 구분한다.

- food: 맛, 식감, 양, 음식 품질
- service: 직원 응대, 주문, 서빙
- price: 가격, 가성비
- atmosphere: 분위기, 공간, 소음
- wait: 웨이팅, 대기시간
- revisit: 재방문 의사
- recommendation: 추천 의사
- hygiene: 위생, 이물질, 재사용
- general: 전반적인 평가

각 영역의 중요도를 동일하게 처리하지 않는다.

- 음식, 재방문, 추천은 비교적 중요하게 반영한다.
- 단순 가격 부담, 웨이팅, 소음은 상대적으로 약하게 반영한다.
- 위생과 심각한 서비스 문제는 강하게 반영한다.

장점:
"맛은 훌륭하지만 웨이팅이 길다"와 같은 리뷰에서 웨이팅 불편 하나 때문에 전체 별점이 지나치게 낮아지는 문제를 줄일 수 있다.


[8] 과소평가와 과대평가 동시 보정

Positive Floor:
- 강한 긍정 근거가 충분하고 명확한 부정이 없을 때 긍정 리뷰가 2점대로 떨어지는 문제를 방지한다.

Negative Cap:
- 위생 문제, 심각한 서비스 문제, 재방문 거절 등 명확한 부정이 있으면 높은 별점이 나오지 않도록 제한한다.

Mixed Review Cap:
- 긍정과 부정이 함께 존재하는 리뷰가 무조건 4.5~5점으로 올라가지 않도록 제한한다.

장점:
긍정 리뷰의 과소평가와 부정 리뷰의 과대평가를 한쪽으로 치우치지 않게 함께 제어한다.


[9] 설명 가능한 감성 별점

최종 결과에는 sentiment_star뿐 아니라 판단에 사용된 근거와 조정 이유가 함께 저장된다.

예시:
sentiment_star: 4.21

matched_words:
- 맛있다:+1[token]
- 재방문 의사:+2[revisit_positive_phrase]
- 비싸다:-0.5[token]

장점:
- 분석 결과가 잘못됐을 때 원인을 확인하기 쉽다.
- 감성사전, 문맥 규칙, 토큰 보정 중 어느 부분을 수정해야 하는지 추적할 수 있다.
- 블랙박스 모델보다 발표와 결과 검토에 유리하다.


[10] 실제 작성 별점은 성능 평가에만 사용

- 리뷰 작성자가 남긴 rating은 sentiment_star 계산에 사용하지 않는다.
- sentiment_star 계산이 완료된 후 실제 rating과의 차이를 비교한다.
- rating은 diff, diff_abs 계산과 오류 분석에만 사용한다.

장점:
실제 별점을 복사하거나 실제 별점에 맞춰 점수를 조작한 방식이 아니라, 리뷰 텍스트만으로 별점을 산출했다는 점을 설명할 수 있다.


[11] 테스트와 오류 진단 자동화

전체 리뷰를 분석하기 전에 다음 테스트를 실행한다.
- 기본 구조 테스트
- 긍정 리뷰 회귀 테스트
- 과대평가 방지 테스트
- 문맥과 평가 대상 구분 테스트
- positive evidence 회복 테스트

분석 후에는 다음 오류 사례를 별도 파일로 저장한다.
- 실제 별점과 분석 별점의 차이가 큰 리뷰
- 고평점인데 낮게 분석된 리뷰
- 저평점인데 높게 분석된 리뷰
- 감성 근거가 부족한 리뷰
- 사전 또는 정규화 계층에 추가할 후보 표현

장점:
새 규칙을 추가했을 때 기존에 정상 처리되던 리뷰가 다시 잘못 분석되는 회귀 오류를 확인할 수 있다.


5. 객관적인 분석 성과

평가 가능한 리뷰 1,482개 기준:

- 실제 별점과 분석 별점의 상관계수: 0.829
- 평균 절대 오차(MAE): 0.631점
- 실제 별점과 1점 이내인 리뷰: 76.0%
- 2점 초과 오류: 0.9%
- 항상 5점을 예측하는 단순 기준선보다 평균 오차 약 47% 감소

이 결과는 현재 데이터에서 리뷰의 감성 방향과 별점 강도를 비교적 잘 추정한다는 것을 보여준다.


6. 핵심적인 장점

1) 설명 가능성
- 별점뿐 아니라 별점이 나온 이유를 확인할 수 있다.

2) 맛집 리뷰 도메인 특화
- 웨이팅, 재방문, 추천, 맛의 균형, 메뉴 사이즈, 가격 부담 등 맛집 리뷰에서 자주 등장하는 상황을 처리한다.

3) 문맥 오류 감소
- 감성 단어가 존재한다는 이유만으로 무조건 점수화하지 않는다.

4) 과대평가와 과소평가 동시 제어
- 긍정과 부정 어느 한쪽만 과하게 반영하지 않도록 설계했다.

5) 지속적으로 개선 가능한 구조
- 오류 사례와 비활성 evidence를 확인하여 감성사전, 토큰 보정, 문맥 규칙 중 적절한 부분을 수정할 수 있다.


7. 한계점

[1] 규칙 기반 시스템의 유지보수 비용

- 문맥 규칙과 phrase rule이 많아질수록 코드가 복잡해진다.
- 새로운 규칙이 기존 규칙과 충돌할 수 있다.
- 규칙 적용 순서가 결과에 영향을 줄 수 있다.
- 특정 오류를 수정하면 다른 리뷰 결과가 나빠질 수 있다.


[2] 처음 보는 표현에 대한 한계

- 사전이나 pattern에 없는 신조어, 은어, 오타, 반어 표현은 탐지하지 못할 수 있다.
- 같은 표현도 문맥에 따라 의미가 달라 규칙만으로 안정적으로 처리하기 어렵다.


[3] 복잡한 문장 전체 의미를 완전히 이해하지 못함

- 평가 대상, 인용, 과거·현재를 구분하는 기능이 있지만 모든 문장을 정확히 해석하지는 못한다.
- 긴 리뷰에서 여러 대상과 시점이 섞이면 잘못된 evidence가 활성화되거나 실제 감성이 제거될 수 있다.


[4] 분석 별점이 중간값으로 모이는 경향

- 실제 1점 리뷰가 2점대에 가깝게 분석될 수 있다.
- 실제 5점 리뷰가 4점대 중반에 머물 수 있다.
- 감성 방향은 비교적 잘 판단하지만 극단적인 감성 강도를 약하게 표현하는 경향이 있다.


[5] 현재 데이터에 맞춰진 규칙일 가능성

- 현재 데이터의 오류 사례를 반복적으로 분석하며 규칙을 개선했다.
- 현재 데이터에서는 좋은 성능을 보이지만, 새로운 식당이나 다른 플랫폼에서도 같은 성능이 나오는지는 별도 검증이 필요하다.
- 규칙 수정에 사용하지 않은 독립 테스트셋으로 일반화 성능을 확인해야 한다.


[6] 수작업으로 결정한 가중치와 기준

- Aspect 가중치와 positive floor, negative cap 기준은 모델이 자동 학습한 값이 아니다.
- 오류 사례 분석을 바탕으로 사람이 설정했으므로 항상 최적이라고 단정할 수 없다.


[7] 실제 별점도 완벽한 정답은 아님

- 리뷰 내용은 부정적이지만 작성 별점은 5점인 사례처럼 본문과 rating이 충돌할 수 있다.
- 따라서 분석 별점과 실제 별점의 차이가 항상 감성분석 오류라고 볼 수는 없다.


8. 발표에서 강조할 최종 특징

이 시스템의 핵심은 감성 단어를 많이 찾는 것이 아니라, 탐지된 표현이 현재 식당에 대한 실제 감성 근거인지 검증하고, 이를 평가 영역별로 반영하여 설명 가능한 별점을 산출한다는 점이다.

구성 요소:

감성사전 기반 탐지
+ 토큰화 오류 보정
+ 문장형 pattern 탐지
+ 문맥 및 평가 대상 검증
+ Evidence 기반 점수 계산
+ Aspect별 가중치
+ 과대·과소평가 보정
+ 자동 테스트 및 오류 진단

과장 없이 표현하면 다음과 같이 소개할 수 있다.

"규칙 기반 방식의 설명 가능성을 유지하면서, 단순 감성사전 분석의 문맥 오류를 단계적으로 보완한 맛집 리뷰 감성 별점 산출 시스템입니다."
